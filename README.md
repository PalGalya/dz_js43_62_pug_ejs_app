# Express сервер з PUG/EJS, статичними файлами, Cookies та JWT

> 📚 **Базова версія документації**: [`README_v1_basic.md`](./README_v1_basic.md)

Цей проект демонструє повноцінний Express додаток з розширеною функціональністю:

## 🚀 **Ключові можливості**

### 🎨 **Dual Template Engine**

- **PUG** для сторінок користувачів (`/users`, `/users/:id`)
- **EJS** для сторінок статей (`/articles`, `/articles/:id`)

### 📁 **Static Files & Favicon**

- Favicon для всіх HTML-сторінок
- Статичні ресурси (CSS, зображення)

### 🍪 **Cookies Management**

- Збереження теми оформлення (світла/темна)
- Persistent налаштування користувача

### 🔐 **JWT Authentication**

- Реєстрація та авторизація користувачів
- Захищені маршрути з JWT middleware
- HTTP-only cookies для безпеки

### 🌙 **Theme Switching**

- Динамічна зміна теми інтерфейсу
- Збереження вибору в cookies

## 📋 **Технічний стек**

- **Backend**: Node.js, Express.js
- **Template Engines**: PUG, EJS
- **Authentication**: JSON Web Tokens (JWT)
- **Security**: bcryptjs для хешування паролів
- **Cookies**: cookie-parser
- **Frontend**: Vanilla JavaScript, CSS3

## ⚠️ **Обмеження проекту**

### 🔴 **Критичні обмеження для production:**

- **In-Memory Storage**: Користувачі зберігаються тільки в пам'яті - **всі дані втрачаються при перезапуску сервера**
- **JWT Secret**: Використовується .env файл, але за замовчуванням fallback значення (змініть у production!)
- **No Database**: Відсутня постійна база даних (MongoDB, PostgreSQL, тощо)
- **Session Management**: Немає централізованого управління сесіями

### 🟡 **Технічні обмеження:**

- **User Storage**: Максимальна кількість користувачів обмежена RAM
- **Data Persistence**: Тестові дані (користувачі, статті) захардкоджені
- **Scalability**: Не призначено для великої кількості користувачів
- **Security**: Basic реалізація без advanced безпекових заходів

### 💡 **Для production потрібно:**

- Інтеграція з базою даних (MongoDB/PostgreSQL)
- Redis для зберігання сесій
- Proper secret management (Azure Key Vault, AWS Secrets Manager)
- Rate limiting та додаткові security заходи
- Логування та моніторинг

## ⚙️ **Middleware та архітектура**

### 🔧 **bin/www - Точка входу**
Файл `bin/www` є стандартною точкою входу Express додатку:
- Налаштовує HTTP сервер
- Обробляє помилки запуску
- Управляє портом (з .env або за замовчуванням 3000)
- Запускає сервер та обробляє SIGTERM сигнали

### 🛠️ **app.js - Middleware Stack**
```javascript
// Middleware для theme cookies (рядки 30-35)
app.use((req, res, next) => {
  res.locals.theme = req.cookies.theme || 'light';
  res.locals.user = req.cookies.user || null;
  next();
});
```

**Функції middleware:**
- Автоматично читає theme з cookies для всіх шаблонів
- Встановлює `res.locals.theme` та `res.locals.user`
- Доступно у всіх PUG та EJS шаблонах без додаткових налаштувань

## 📚 **Детальна функціональність**

### 🏠 **Основні маршрути (PUG)**

### Маршрути з EJS шаблонізатором

- **GET /articles** - Список всіх статей з використанням EJS
- **GET /articles/:articleId** - Повна стаття з контентом з використанням EJS

### Маршрути авторизації (JWT + Cookies)

- **POST /auth/register** - Реєстрація нового користувача (валідація: мін. 3 символи username, мін. 6 символів password)
- **POST /auth/login** - Вхід користувача (генерує JWT токен на 1 годину)
- **POST /auth/logout** - Вихід користувача (очищає cookies)
- **GET /auth/profile** - Захищений маршрут (потрібен JWT токен в cookies)
  - **Успішна відповідь**: 
    ```json
    {
      "message": "User profile",
      "user": {
        "id": 1,
        "username": "john_doe",
        "registeredAt": "Unknown"
      },
      "tokenInfo": {
        "expiresIn": "1 hour from login",
        "issuedFor": "john_doe"
      }
    }
    ```
  - **Помилка 401**: `{"message": "Access denied"}` (відсутній токен)
  - **Помилка 403**: `{"message": "Invalid token"}` (недійсний токен)
- **POST /auth/theme** - Зміна теми оформлення (light/dark, зберігається на 30 днів)

### Статичні файли

- **GET /favicon.ico** - Favicon для всіх сторінок
- **GET /stylesheets/style.css** - CSS стилі
- **GET /images/\*** - Зображення

## Обробка помилок

Сервер включає систему обробки помилок:

- **404 Not Found** - для неіснуючих сторінок
- **500 Internal Server Error** - для серверних помилок
- **Неіснуючі користувачі/статті** - відображають відповідні повідомлення про помилку

Всі помилки обробляються через шаблон `error.pug`, який відображає:

- Код помилки
- Повідомлення про помилку
- Навігаційні посилання для повернення

## 🔒 **Безпека**

### JWT Токени

- Збереження в **HTTP-only cookies** для захисту від XSS
- Час життя токену: **1 година**
- Автоматичне очищення при виході

### Паролі

- Хешування через **bcryptjs** (salt rounds: 10)
- Паролі ніколи не зберігаються у відкритому вигляді

### Cookies

- Налаштування теми зберігаються **30 днів**
- Безпечна передача JWT токенів

## Налаштування шаблонізаторів

У файлі `app.js` налаштовано підтримку двох шаблонізаторів:

```javascript
// PUG як основний шаблонізатор
app.set("views", path.join(__dirname, "views"));
app.set("view engine", "pug");

// Додаткове налаштування EJS для статей
app.engine("ejs", require("ejs").renderFile);
```

### PUG (користувачі)

- Використовує базовий `layout.pug` з блоком `content`
- Мінімалістичний синтаксис без закривних тегів
- Файли: `views/pug/users.pug`, `views/pug/user-detail.pug`

### EJS (статті)

- Повноцінні HTML документи з EJS вставками
- HTML-подібний синтаксис з JavaScript вставками `<%= %>`
- Файли: `views/ejs/articles.ejs`, `views/ejs/article-detail.ejs`

## CSS стилізація

Єдиний файл стилів `/stylesheets/style.css` застосовується до всіх сторінок:

- Адаптивний дизайн з CSS Grid
- Стилі для навігації, карток та кнопок
- Респонсивний layout для мобільних пристроїв
